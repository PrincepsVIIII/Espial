# API conventions

These conventions apply to browser, administration, and adapter-management APIs.
Adapter process messages use the separate [adapter protocol](ADAPTER_PROTOCOL.md).

## Resource model

- Base path: `/api/v1`.
- JSON media type: `application/json`; UTF-8 only.
- Field names: `snake_case` in JSON and schemas.
- IDs: opaque UUID strings generated by Core. External/vendor IDs are separate.
- Time: RFC 3339 timestamps in UTC with an explicit `Z`; durations are integer
  seconds unless the field name declares another unit.
- Optional fields are omitted rather than set to `null`, unless clearing a nullable
  value is the documented operation.
- Unknown enum values must fail writes and be tolerated visibly on reads by clients.

## HTTP behavior

- `GET` is safe; `PUT` replaces a known resource; `PATCH` applies a documented
  merge patch; `POST` creates or invokes; `DELETE` is idempotent.
- Successful creation returns `201` with `Location`. Async work returns `202` with
  an operation resource. Empty success returns `204`.
- Mutations accept `Idempotency-Key` where retries could duplicate work.
- Mutable administration resources expose an `ETag`; updates use `If-Match` and
  return `412` on stale writes.
- Requests receive or generate `X-Request-ID`; it appears in logs, audit records,
  errors, and adapter calls spawned by the request.
- Default request bodies are capped at 1 MiB. Adapter manifests/configuration may
  define a lower endpoint-specific limit.

## Errors

Non-2xx JSON responses use:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Request validation failed.",
    "request_id": "01J...",
    "fields": [{"field": "display_name", "code": "required"}]
  }
}
```

Messages are safe for operators and never include secrets, SQL, stack traces, raw
adapter output, or existence details that enable account enumeration.

## Collections

Use cursor pagination: `?limit=50&cursor=...`, with a default of 50 and maximum of
200. Responses include `items` and an omitted `next_cursor` when complete. Filters
are explicit query parameters; repeated parameters mean OR within that field and
AND across different fields. Stable ordering always includes `id` as a tiebreaker.

## Authentication and authorization

Browser sessions use the cookie and CSRF rules in
[authentication](AUTHENTICATION.md). Unauthenticated requests return `401`;
authenticated but unauthorized requests return `403`. Resource existence may be
concealed with `404` where disclosure itself is sensitive.

## Phase 1 surface

```text
GET  /api/v1/health/live
GET  /api/v1/health/ready
GET  /api/v1/auth/capabilities
POST /api/v1/auth/local/login
POST /api/v1/auth/logout
GET  /api/v1/auth/session
GET  /api/v1/admin/ping              temporary Slice 1.2 RBAC acceptance probe
GET  /api/v1/overview
GET  /api/v1/resources
GET  /api/v1/resources/{id}
GET  /api/v1/integrations
GET  /api/v1/integrations/{id}
POST /api/v1/integrations
PUT  /api/v1/integrations/{id}/configuration
GET  /api/v1/events/stream
GET  /api/v1/audit                   administrator only
```

Resource filters are repeated `state`, `kind`, and `integration` values plus a
single `stale` boolean. Integration filters are repeated `adapter_id` and
`runtime_state` values plus a single `enabled` boolean. Audit filters are repeated
`action`, `result`, and `target_type` values, with one `actor_user_id`, `from`, and
`to`. `stale=true` matches the stale state only; unknown remains an explicit state
filter. Audit windows default to the previous 24 hours and cannot exceed 31 days.

Integration creation accepts only adapter IDs in Core's immutable trusted registry.
Configuration replacement requires the current response `ETag` in `If-Match`;
missing, stale, and unknown-adapter preconditions return `428`, `412`, and `409`
respectively. Both mutations require `integrations:manage`, trusted origin, CSRF,
bounded JSON, and an audit record. Configuration values and secret-reference values
never appear in read models or audit summaries; only their key names do.

## Live events

SSE messages have `id`, `event`, and a JSON `data` object with `schema_version`,
`resource_id` or `integration_id`, and `changed_at`. They are invalidations, not a
second source of truth. Send a heartbeat comment every 15 seconds. Honor
`Last-Event-ID` within a bounded replay window; otherwise emit `resync_required`.
The heartbeat also revalidates the session and `overview:read` permission. A lost or
revoked session closes the stream within that interval. Concurrent streams are
bounded and excess clients receive `503` with `Retry-After`.

## Compatibility

Additive fields and endpoints are backward-compatible within v1. Removing fields,
changing semantics/types, or making optional data required needs a new API version
or an announced deprecation window. Schemas and representative fixtures are tested
in CI before backend and generated frontend types are accepted.
